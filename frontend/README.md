### API Call Convention

`apiRequest` in [src/services/api/client.js](src/services/api/client.js) attaches the JWT, sets
JSON headers, converts non-2xx responses into thrown `Error`s carrying `status`/`data`, and clears
the token plus fires `AUTH_EXPIRED_EVENT` on a 401.

```js
// src/services/<module>/<name>.service.js
import { apiRequest } from "@/services/api/client";

export const listThings = (params) => apiRequest(`/api/things?${new URLSearchParams(params)}`);
```

A service may drop to raw `fetch`/`XMLHttpRequest` when `apiRequest` cannot express the call —
blob downloads, upload progress, server-sent events — as
[india-post.service.js](src/services/location/india-post.service.js) does.
`src/lib/apiClient.js` is only a re-export shim; import from `@/services/api/client` in new code.

### Saving a File

**Nothing builds its own file path.** Every download goes through
[src/lib/projectStorage.mjs](src/lib/projectStorage.mjs), which resolves it beneath the Project Root
Path set in ⋮ → Project Settings:

```text
Project Settings → Root Path → projectStorage → <project> → <module folder> → the file
```

```js
import { PROJECT_FOLDERS, openProjectStorage } from "@/lib/projectStorage.mjs";

const storage = await openProjectStorage({ rootPath, projectName, request: true });
await storage.write({ blob, fileName, folder: PROJECT_FOLDERS.selectedImages, subPath: [shoot] });
```

`saveProjectFile()` is the single-file form. Module folders are `PROJECT_FOLDERS` — Image Selection,
Selected Images, Retouches, Frames, Calendar, Downloads — and every name is sanitised, so a project
called `..` cannot write outside the root. Writing needs the folder the studio picked once through
the browser's picker; with no root, no grant, or a browser without the File System Access API, the
same call falls back to the browser's Downloads folder and reports why through
`storageReasonMessage()`.

## Installing as an App (PWA)

The application installs to a home screen or a dock and launches in its own window with no browser
chrome. **There is no service worker**, by decision: offline behaviour and push notifications are a
later piece of work, and installing needs neither.

| File | What it settles |
| --- | --- |
| [src/app/manifest.js](src/app/manifest.js) | Served at `/manifest.webmanifest`, re-read every 60 s. Name and icons from Settings → Branding (see below), `start_url: "/"`, `scope: "/"`, `display: "standalone"`, and the white splash ground. |
| [src/app/layout.js](src/app/layout.js) | `appleWebApp` (its title the studio name), `icons.apple` and the legacy `apple-mobile-web-app-capable` for iOS, and the `viewport` export carrying `themeColor` as a light/dark pair. |
| [src/lib/serverStudioBranding.js](src/lib/serverStudioBranding.js) | `studioAppName` and `appIconUrl`: the studio's name and favicon-drawn icons, or the bundled ones. |
| [public/icons/](public/icons/) | The five bundled PNGs — the fallback whenever the studio has no favicon or the API cannot draw it. |
| [test/pwa-install.test.mjs](test/pwa-install.test.mjs) | Pins every rule below, because breaking one changes nothing on screen. |

Where to find the command, per platform — it is not called the same thing twice:

| Platform | How somebody installs it |
| --- | --- |
| Android Chrome | ⋮ → **Add to Home screen** → Install |
| Chrome / Edge desktop | ⋮ → **Cast, save and share** → **Install page as app** |
| iPhone / iPad Safari | **Share** → **Add to Home Screen** |
| macOS Safari 17+ | **File** → **Add to Dock** |
| Firefox desktop | Not supported — Mozilla removed site installation. Nothing to fix here. |

The address bar's own install icon, and any custom **Install** button built on `beforeinstallprompt`,
are a separate matter: Chrome dropped the service-worker requirement for the **menu** item (mobile
108, desktop 112) but still wants a `fetch` handler before it offers the prompt itself. So a service
worker buys the in-app button, not the ability to install.

Installing works only on **HTTPS** or `localhost`. Production is behind nginx and Let's Encrypt, so
this is already true there; a plain-HTTP staging host offers no Install anywhere.

Three things to know before changing any of it:

- **`themeColor` belongs to the `viewport` export, not `metadata`.** Next 16 ignores it in
  `metadata`, silently. It is a pair because a white system bar around a dark page is the seam that
  gives away a web view; the manifest's own `theme_color` carries one colour and cannot express it.
- **The installed app's name and icon follow Settings → Branding, and ours are the fallback.** The
  name is the studio name (cut by the launcher if long), the icons are drawn by the API from the
  favicon at `/api/public/app-icon/<variant>.png` — a white square with the mark centred, the
  maskable pair at 70%. With no studio name or favicon, or the API unreachable or unable to draw
  it, the bundled name and PNGs are used, so installing never depends on the API. A manifest is
  read once, when the home screen icon is made: a change in Settings reaches new installs, and one
  already on a device keeps what it was given until it is installed again (iOS never refreshes it;
  Android Chrome may, on its own schedule).
- **`maskable` icons are not the same file as `any`.** Android cuts its own shape from a maskable
  icon and keeps only the central 80%, so those two are the mark at 70% on a full-bleed white
  square. Handing it the `any` file clips the B and the C.
- **iOS needs `apple-mobile-web-app-capable` as well as `capable: true`.** Next renders the latter
  as `mobile-web-app-capable`, which is the standard name and which iOS has honoured only since 17.
  An older iPhone reads the `apple-` one alone, and without it the home screen icon opens inside
  Safari with the address bar — the one thing installing was for.

Regenerating the icons after the brand mark changes — run from `frontend/`, `sharp` comes with Next:

```js
// node --input-type=module, reading public/brand/favicon.svg
const render = (size) => sharp(svg, { density: 900 }).resize(size, size);
await render(192).png().toFile("public/icons/icon-192.png");            // and 512
await render(180).flatten({ background: "#ffffff" })                    // iOS draws no alpha
  .png().toFile("public/icons/apple-touch-icon-180.png");
// maskable: composite render(size * 0.7) centred on a white size×size square
```

Verify with DevTools → Application → Manifest (it must say installable, with no icon warnings), and
install it on a real Android device to confirm the mark is not cropped.

- Used by two or more modules → promote it to `components/shared/` (or `ui/` for overlays and

## Rule 2 — Everything Must Be Responsive Down to Mobile

Every screen, dialog, table, and form must be usable on a ~360px-wide phone. This is part of "done",
not a follow-up ticket.

- **Mobile-first.** Write the phone layout with unprefixed classes, then add `sm:` / `md:` / `lg:`
  for wider screens. Never write a desktop layout and try to claw it back with `max-*` breakpoints.
- **No page-level scrolling in the app shell.** A module screen fills the shell exactly; scrolling
  belongs to the panes inside it. Carry `min-h-0` down every flex/grid level and give the scrolling
  pane `overflow-y-auto`. Avoid `min-h-[…]` floors on layout containers — they reintroduce a page
  scrollbar. Do not size a page with `100dvh` minus hard-coded bar heights; fill the flex column
  `AppShell` already provides.
- **No horizontal page scroll.** Flex and grid children that hold text or tables need `min-w-0`;
  wide content (tables, toolbars, code) scrolls inside its own `overflow-x-auto` container.
- **Multi-column layouts collapse.** Sidebars and side panels stack (or become drawers/sheets)
  below `md`. The Image Selection workspace is the reference: `grid-cols-1` by default,
  `md:grid-cols-[…]` above it.
- **Dialogs and full-screen panels** are full-bleed on phones and constrained on desktop, with
  `max-h-[calc(100dvh-…)]` plus internal scrolling — see [ui/Dialog.js](src/components/ui/Dialog.js).
  A dialog grows with its content by default; one that shows a list passes `height="mid"` (a short
  list) or `height="tall"` (a long one) so the card keeps one size and the rows scroll inside it.
  The viewport cap still applies on a phone.
- **Tap targets** stay at least `h-8`/`w-8` (32px) with real spacing; icon-only controls need
  `aria-label`.
- **No fixed pixel widths** on containers. Use `w-full` with `max-w-*`, `minmax(0,1fr)` grid tracks,
  and fluid gaps.
- **Check it before saying it works:** resize to ~360px, ~768px, and ~1280px. Confirm nothing is
  clipped, no horizontal scrollbar appears, and every control is reachable.

Existing breakpoint use in this repo is `sm:` for most density switches, `md:` for shell/sidebar
layout changes, and `lg:`/`xl:` for wide-desktop refinements.
