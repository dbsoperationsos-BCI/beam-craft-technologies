# Speak-up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a confidential, one-way "Speak-up" complaint box — an employee writes HR something personal (type, subject, description, an optional attachment); only HR sees who wrote it.

**Architecture:** One new `SpeakUp` table and a thin HRM backend module (`create` / `mine` / `all` / `attachment`) behind two new permissions, `HRM / Speak-up` (submit + own history) and `HRM / Speak-up Review` (HR reads everyone's). The screen is not new — it is two more entries in Employee Attendance's existing section dropdown, gated the same way its `"Rules"` section already is by a permission distinct from the page's own route guard.

**Tech Stack:** Express + Zod + Prisma/MySQL (backend), Next.js + the existing `shared`/`ui` component library (frontend), Cloudflare R2 via `services/objectStorage.js` for the private attachment.

**Spec:** [docs/superpowers/specs/2026-09-29-speak-up-design.md](../specs/2026-09-29-speak-up-design.md) — the plan below argues from it; read both.

## Global Constraints

- Confidential to HR, not anonymous (spec: Intent). The employee's id and name are always stored and shown to whoever holds the Review permission.
- One-way inbox: no status field, no reply, no `PATCH`/`DELETE` route (spec: Intent, Backend).
- `type` is a fixed six-value enum, exactly: `Team / Manager Issue`, `HR / People`, `Work Environment`, `Suggestion`, `App / System Issue`, `Other` (spec: Intent).
- Fields and labels are exact: **Type\*** (required), **Subject** (required), **"What happened?"** (required, long text), **Attachment** (optional, one file) (spec: Intent).
- Not branch-scoped, on purpose — `HRM / Speak-up Review` sees every row studio-wide, no `dataScope` narrowing (spec: Data).
- Lives inside `EmployeeAttendancePage`, not a new page or sidebar entry; its route is still gated by `HRM / Employee Attendance` (spec: Why inside Employee Attendance).
- Every new permission row goes into the catalogue **and** a migration that also grants `SUPER_ADMIN`, per IAM.md step 10 — the seed alone never reaches production.
- Both permissions are `NO_MENU_ENTRY` — they open no sidebar row of their own.
- The attachment is a `{ name, data }` base64 data URL from `FileUploadField`, not multipart — decoded server-side and stored through `services/objectStorage.js`'s `uploadPrivateObject`/`getPrivateObject` (spec: Attachment storage). Nothing about the file is ever public; only the authenticated stream endpoint reads it back.
- Never trust an `employeeId` from the request body — always resolved from `req.user.linkedEmployeeId` server-side (CLAUDE.md Rule 4).

## Review Focus

- **Attachment omitted entirely.** A `null`/absent `attachment` in the create payload must still succeed — `title`/`description` alone are the only hard requirements. A person with nothing to attach should never be blocked.
- **`type` sent as anything outside the six values** (a stale client, a hand-crafted request) must be refused by the Zod enum with a field-level message, not silently accepted as free text.
- **Someone with `HRM / Speak-up` but not `HRM / Speak-up Review` requesting the "everyone's" list directly** (bypassing the UI, calling the API) must be refused by the route guard, not merely have the section hidden client-side.
- **The attachment-download endpoint asked for a row that belongs to someone else**, by an employee who holds only `HRM / Speak-up` (not Review) — must be refused, not streamed, even though the row's id is guessable (sequential integer).
- **A login with no linked employee at all** (`req.user.linkedEmployeeId` empty — an admin-only account) calling `POST /api/hrm/speak-up` must get a clear refusal rather than a row silently written with a null employee and "Unknown" as its name, which would be unreadable and untraceable in the Review list.

```sql

-- Speak-up: a confidential line to HR. Two permissions, `HRM / Speak-up` (submit + own history)
-- and `HRM / Speak-up Review` (HR reads everyone's) - here as a migration rather than only in the
-- seed, because the seed cannot run on production and a guard naming a permission the table does
-- not hold refuses everybody but a Super Admin. `seeds/permission-catalogue.js` holds the same two
-- rows and upserts on `module + feature + level`, so a seeded environment finds these rather than
-- making a second pair.
--
-- Who gets it, to start with (Role Management can change any of it afterwards):
--   * Read / Write for SUPER_ADMIN.
--   * Read / Write for `Speak-up`, for every role holding `HRM / Employee Attendance` at any level -
--     everyone who can already raise their own leave request is meant to be able to speak up too.
--   * Read / Write for `Speak-up Review`, for every role holding `HRM / Employee Management` at
--     Read / Write - HR, who post and edit employee records.
-- The Admin Permission set every Branch Admin carries follows the same two rules.

INSERT INTO `permission` (`id`, `module`, `feature`, `level`, `display_name`, `description`, `is_active`, `created_at`, `updated_at`)
SELECT UUID(), 'HRM', 'Speak-up', 'SPEAK_UP', 'Speak-up',
       'Write HR something personal, and see your own past Speak-ups',
       1, NOW(3), NOW(3)
WHERE NOT EXISTS (
  SELECT 1 FROM `permission` AS `existing`
  WHERE `existing`.`module` = 'HRM' AND `existing`.`feature` = 'Speak-up' AND `existing`.`level` = 'SPEAK_UP'
);

INSERT INTO `permission` (`id`, `module`, `feature`, `level`, `display_name`, `description`, `is_active`, `created_at`, `updated_at`)
SELECT UUID(), 'HRM', 'Speak-up Review', 'SPEAK_UP_REVIEW', 'Speak-up Review',
       'Read every Speak-up submitted, across every branch',
       1, NOW(3), NOW(3)
WHERE NOT EXISTS (
  SELECT 1 FROM `permission` AS `existing`
  WHERE `existing`.`module` = 'HRM' AND `existing`.`feature` = 'Speak-up Review' AND `existing`.`level` = 'SPEAK_UP_REVIEW'
);

-- SUPER_ADMIN holds every permission there is (20260917100000).
INSERT INTO `role_permission` (`id`, `roleId`, `permissionId`, `access_level`, `created_at`, `updated_at`)
SELECT UUID(), `role`.`id`, `permission`.`id`, 'READ_WRITE', NOW(3), NOW(3)
  FROM `role` JOIN `permission` ON `permission`.`module` = 'HRM' AND `permission`.`feature` IN ('Speak-up', 'Speak-up Review')
  LEFT JOIN `role_permission` ON `role_permission`.`roleId` = `role`.`id` AND `role_permission`.`permissionId` = `permission`.`id`
 WHERE `role`.`name` = 'SUPER_ADMIN' AND `role_permission`.`id` IS NULL;

-- Read / Write on Speak-up for every role holding Employee Attendance at any level.
INSERT INTO `role_permission` (`id`, `roleId`, `permissionId`, `access_level`, `created_at`, `updated_at`)
SELECT UUID(), `grant`.`roleId`, `new`.`id`, 'READ_WRITE', NOW(3), NOW(3)
FROM `role_permission` AS `grant`
JOIN `permission` AS `old`
  ON `old`.`id` = `grant`.`permissionId` AND `old`.`module` = 'HRM' AND `old`.`feature` = 'Employee Attendance'
JOIN `permission` AS `new`
  ON `new`.`module` = 'HRM' AND `new`.`feature` = 'Speak-up' AND `new`.`level` = 'SPEAK_UP'
WHERE `grant`.`access_level` IN ('READ', 'READ_WRITE')
  AND NOT EXISTS (SELECT 1 FROM `role_permission` AS `already` WHERE `already`.`roleId` = `grant`.`roleId` AND `already`.`permissionId` = `new`.`id`);

-- Read / Write on Speak-up Review for every role that writes Employee Management.
INSERT INTO `role_permission` (`id`, `roleId`, `permissionId`, `access_level`, `created_at`, `updated_at`)
SELECT UUID(), `grant`.`roleId`, `new`.`id`, 'READ_WRITE', NOW(3), NOW(3)
FROM `role_permission` AS `grant`
JOIN `permission` AS `old`
  ON `old`.`id` = `grant`.`permissionId` AND `old`.`module` = 'HRM' AND `old`.`feature` = 'Employee Management'
JOIN `permission` AS `new`
  ON `new`.`module` = 'HRM' AND `new`.`feature` = 'Speak-up Review' AND `new`.`level` = 'SPEAK_UP_REVIEW'
WHERE `grant`.`access_level` = 'READ_WRITE'
  AND NOT EXISTS (SELECT 1 FROM `role_permission` AS `already` WHERE `already`.`roleId` = `grant`.`roleId` AND `already`.`permissionId` = `new`.`id`);

-- The Branch Admin set: Read / Write on both, following the same two rules.
INSERT INTO `branch_admin_permission` (`id`, `permission_id`, `access_level`, `created_at`, `updated_at`)
SELECT UUID(), `new`.`id`, 'READ_WRITE', NOW(3), NOW(3)
FROM `branch_admin_permission` AS `grant`
JOIN `permission` AS `old`
  ON `old`.`id` = `grant`.`permission_id` AND `old`.`module` = 'HRM' AND `old`.`feature` = 'Employee Attendance'
JOIN `permission` AS `new`
  ON `new`.`module` = 'HRM' AND `new`.`feature` = 'Speak-up' AND `new`.`level` = 'SPEAK_UP'
WHERE `grant`.`access_level` IN ('READ', 'READ_WRITE')
  AND NOT EXISTS (SELECT 1 FROM `branch_admin_permission` AS `already` WHERE `already`.`permission_id` = `new`.`id`)
LIMIT 1;

INSERT INTO `branch_admin_permission` (`id`, `permission_id`, `access_level`, `created_at`, `updated_at`)
SELECT UUID(), `new`.`id`, 'READ_WRITE', NOW(3), NOW(3)
FROM `branch_admin_permission` AS `grant`
JOIN `permission` AS `old`
  ON `old`.`id` = `grant`.`permission_id` AND `old`.`module` = 'HRM' AND `old`.`feature` = 'Employee Management'
```

- [ ] **Step 1: Write the controller**

Create `backend/src/modules/hrm/speak-up/controller.js`:

```js
const path = require("node:path");
const { z } = require("zod");
const prisma = require("../../../config/db");
const iamService = require("../../../services/iam.service");
const { uploadPrivateObject, getPrivateObject } = require("../../../services/objectStorage");

const TYPES = ["Team / Manager Issue", "HR / People", "Work Environment", "Suggestion", "App / System Issue", "Other"];

const attachmentSchema = z.object({
  name: z.string().trim().min(1).max(255),
  data: z.string().trim().min(1),
}).nullable().optional();

const createSchema = z.object({
  type: z.enum(TYPES),
  title: z.string().trim().min(1).max(191),
  description: z.string().trim().min(1),
  attachment: attachmentSchema,
});

function validationError(res, error) {
  return res.status(400).json({ message: "Validation failed", errors: error.flatten() });
}

function handleError(res, error, fallback) {
  if (error.status) return res.status(error.status).json({ message: error.message });
  console.error("Speak-up error:", error);
  return res.status(500).json({ message: fallback, error: error.message });
}

const badRequest = (message) => Object.assign(new Error(message), { status: 400 });

/**
 * Decodes a `{ name, data }` upload (the `FileUploadField` shape, a base64 data URL) into a
 * private object, or `null` when nothing was attached. The extension comes from the original file
 * name rather than the data URL's declared mime type, which a browser can get wrong for an
 * unfamiliar document type; the stored `Content-Type` still comes from the data URL, since that is
 * what the browser needs to render or download the bytes correctly.
 */
async function storeAttachment(attachment) {
  if (!attachment) return null;
  const match = /^data:([^;]+);base64,(.+)$/.exec(attachment.data);
  if (!match) throw badRequest("That attachment could not be read.");
  const [, contentType, base64] = match;
  const buffer = Buffer.from(base64, "base64");
  if (!buffer.length) throw badRequest("That attachment could not be read.");
  const extension = path.extname(attachment.name).slice(1).toLowerCase() || "bin";
  const { key } = await uploadPrivateObject(buffer, { folder: "hrm/speak-up", extension, contentType });
  return { key, name: attachment.name };
}

/** The employee behind this login, or `null` for an account with none - an admin-only user. */
async function callingEmployee(req) {
  const employeeId = Number(req.user?.linkedEmployeeId) || null;
  if (!employeeId) return null;
  return prisma.employee.findFirst({ where: { id: employeeId }, select: { id: true, employeeName: true } });
}

async function create(req, res) {
  const parsed = createSchema.safeParse(req.body);
  if (!parsed.success) return validationError(res, parsed.error);
  try {
    const employee = await callingEmployee(req);
    if (!employee) return res.status(400).json({ message: "Your login is not linked to an employee record, so a Speak-up cannot be attributed to you." });

    const stored = await storeAttachment(parsed.data.attachment);
    const created = await prisma.speakUp.create({
      data: {
        employeeId: employee.id,
        employeeName: employee.employeeName,
        type: parsed.data.type,
        title: parsed.data.title,
        description: parsed.data.description,
        attachmentKey: stored?.key ?? null,
        attachmentFileName: stored?.name ?? null,
      },
    });
    return res.status(201).json({ data: created });
  } catch (error) {
    return handleError(res, error, "Unable to save this Speak-up.");
  }
}

async function mine(req, res) {
  try {
    const employee = await callingEmployee(req);
    const rows = employee
      ? await prisma.speakUp.findMany({ where: { employeeId: employee.id }, orderBy: { createdAt: "desc" } })
      : [];
    return res.json({ data: rows });
  } catch (error) {
    return handleError(res, error, "Unable to load your Speak-ups.");
  }
}

async function all(req, res) {
  try {
    const rows = await prisma.speakUp.findMany({ orderBy: { createdAt: "desc" } });
    return res.json({ data: rows });
  } catch (error) {
    return handleError(res, error, "Unable to load Speak-ups.");
  }
}

/**
 * Streams one attachment back. `HRM / Speak-up Review` may ask for any row; a caller who reached
 * this route only through the base `HRM / Speak-up` guard may ask only for a row that is their
 * own - re-checked here directly against `iamService`, the same way `isAttendanceAdmin` asks a
 * finer question than the route guard already answered, rather than trusted from whichever list
 * the request claims to have come from.
 */
async function attachment(req, res) {
  const id = Number(req.params.id);
  if (!id) return res.status(400).json({ message: "That Speak-up could not be found." });
  try {
    const row = await prisma.speakUp.findUnique({ where: { id }, select: { attachmentKey: true, attachmentFileName: true, employeeId: true } });
    if (!row || !row.attachmentKey) return res.status(404).json({ message: "This Speak-up has no attachment." });

    const canReviewAll = await iamService.hasPermission(req.user.id, "HRM", "Speak-up Review", "READ");
    if (!canReviewAll) {
      const employee = await callingEmployee(req);
      if (!employee || employee.id !== row.employeeId) return res.status(403).json({ message: "You may not read this attachment." });
    }

    const object = await getPrivateObject(row.attachmentKey);
    if (!object) return res.status(404).json({ message: "This attachment is no longer stored." });
    res.setHeader("Content-Type", object.contentType);
    res.setHeader("Content-Disposition", `attachment; filename="${(row.attachmentFileName || "attachment").replace(/"/g, "")}"`);
    res.setHeader("Cache-Control", "private, no-store");
    if (object.contentLength) res.setHeader("Content-Length", String(object.contentLength));
    return object.body.pipe(res).on("error", () => {
      if (!res.headersSent) res.status(404).json({ message: "This attachment is no longer stored." });
    });
  } catch (error) {
    return handleError(res, error, "Unable to load this attachment.");
  }
}

module.exports = { TYPES, create, mine, all, attachment };
```
